# VeloxCache 全链路串联：两个节点的经典例子

> 目标：用一个具体场景，把 `example/test.go -> server -> registry -> peers -> consistenthash -> client -> group -> cache -> store -> lru2` 串成一条可复述的链路。
> 所有引用格式为 `文件:行号`，可以直接跳转。

## 0. 场景设定

```text
服务名:  velox-cache
缓存组:  test
容量:    2 << 20 = 2MB

节点 A:  -port 8001，注册到 etcd 后地址为 192.168.1.5:8001
节点 B:  -port 8002，注册到 etcd 后地址为 192.168.1.6:8001

Getter:  返回 "节点X的数据源值"
```

为了讲解，假设按一致性哈希算出来的归属是：

```text
key_A -> A        key_B -> A        key_C -> B
```

真实归属取决于运行机器的 IP，但链路结构完全一样。

## 1. 进程装配：`example/test.go:13-54`

```text
main
  addr = ":8001"                                          test.go:19
  NewServer(addr, "velox-cache", opts...)                  test.go:23  -> server.go:78
  NewClientPicker(addr)                                   test.go:32  -> peers.go:67
  NewGroup("test", 2<<20, GetterFunc{...})                test.go:38  -> group.go:91
  group.RegisterPeers(picker)                             test.go:46  -> group.go:344
  go node.Start()                                         test.go:49  -> server.go:127
```

三个组件各自初始化了什么：

```text
NewServer        clientv3.New(etcd) + grpc.NewServer + 注册 VeloxCache/健康检查
                 server.go:85,94-103,116,119-121
NewClientPicker  clientv3.New(etcd) + fetchAllServices + go watchServiceChanges
                 peers.go:82,105,110
NewGroup         NewCache(默认 LRU2, 8MB) + singleflight.Group + 注册到全局 groups
                 group.go:97-105,113-120
```

注意 `NewCache` 只保存配置，不创建 Store（`cache.go:49-53`），真正的 LRU2 在第一次读写时才懒初始化（`cache.go:56-85`）。

         value="192.168.1.5:8001", WithLease)             register.go:52-53

etcd 中形成一条绑定租约的记录。节点下线的本质是停止续约，让租约到期自动删除 key。

## 9. 分层职责速查

| 层 | 关键文件 | 职责 |
|---|---|---|
| 应用装配 | `example/test.go` | 组装 Server / Picker / Group |
| 网络服务 | `server.go`, `pb/` | gRPC 收包，委派给本地 Group |
| 网络客户端 | `client.go` | 实现 Peer，把调用翻译成 gRPC |
| 注册发现 | `registry/register.go`, `peers.go` | 租约注册、watch 发现、维护节点视图 |
| 分布式路由 | `consistenthash/` | key -> 归属节点 |
| 并发原语 | `singleflight/`, atomic/mutex | 请求合并、状态保护 |
| 缓存服务 | `group.go`, `cache.go` | 命名空间、回源编排、懒初始化、统计 |
| 存储引擎 | `store/` | LRU / LRU-2、过期、淘汰、后台清理 |

## 10. 已知问题（阅读时的观察点）

1. `selfAddr` 是 `":8001"`，etcd 里是 `"IP:8001"`，导致 `isSelf` 永远为 false。
2. watch 的 Delete 事件用 `event.Kv.Value` 取地址，但 Delete 事件不带 value。
3. `from_peer` 用 context value 传递，跨 gRPC 后丢失。
4. `rebalanceNodes` 持锁调用 `Remove`，自死锁。
5. `Map.Get` 在读锁下修改 `nodeCounts`，存在数据竞争。
6. `Server.Stop` 关闭的 `stopCh` 与注册时使用的不是同一个 channel。
7. `NewServer` 修改包级 `DefaultServerOptions`。
8. `singleflight` 没有 `defer`，fn panic 会让等待者永久阻塞。
9. 写同步只到归属节点，没有失效广播，其他节点可能长期读到旧副本。
10. `Client` 的 `addr`、`svcName`、`etcdCli` 与 `Server.groups` 都是死字段。
